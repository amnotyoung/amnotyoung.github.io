좋은 답변 하나보다 좋은 업무 흐름이 오래 남습니다. 이 과정은 AI를 별도의 대화창이 아니라 파일·도구·지식·동료가 연결되는 작업 환경으로 다룹니다.

01

START

Claude Code에서 시작하기

채팅창에 질문하고 답을 복사하는 방식에서 벗어나 프로젝트 폴더를 작업의 중심으로 둡니다. Claude Code와 Codex가 파일을 읽고, 수정하고, 결과물을 남기는 기본 흐름을 익힙니다.

  • 프로젝트 중심대화가 아니라 폴더와 파일을 업무의 지속적인 맥락으로 사용합니다.
  • 흐름 중심한 번의 멋진 답변보다 반복하고 검증할 수 있는 절차를 만듭니다.
02

CONNECT

MCP로 실제 자료와 도구 연결하기

MCP는 AI가 외부 자료와 도구를 정해진 방식으로 사용할 수 있게 하는 연결 규격입니다. KOICA 규정, 국가법령, HWP 문서, 회의록을 각각 찾는 데서 끝나지 않고 하나의 업무 질문으로 연결합니다.

  • 근거 확인내부 규정과 외부 법령의 역할을 구분하고 원문을 다시 확인합니다.
  • 업무 연결검색·변환·회의 기록을 보고서 작성 흐름으로 조합합니다.
03

TRANSFORM

바이너리에서 텍스트로

파일이 화면에서 열린다고 AI가 구조까지 잘 이해하는 것은 아닙니다. PDF·HWPX·Office 문서는 원본을 보존한 채 Markdown, CSV, HTML 같은 작업용 텍스트로 변환하고 결과를 검산합니다.

  • 원본 보존변환본은 작업용으로 사용하고 원본 파일은 별도로 유지합니다.
  • 텍스트 우선변경점 비교, 검색, 자동화가 쉬운 중간 형식을 선택합니다.
04

KNOWLEDGE

Brain dumping에서 LLM Wiki로

자료를 완벽하게 분류한 뒤 시작하려 하지 않습니다. 먼저 쌓고 AI와 함께 정리하면서 페이지와 링크가 보이는 Wiki로 바꿉니다. 사람이 아는 주관적 관련성을 더하고, LLM은 링크 점검과 목록 갱신 같은 정리 노동을 맡습니다.

  • 먼저 축적정리 부담 때문에 기록 자체가 멈추지 않도록 합니다.
  • 관계 편집검색 결과를 소비하는 데서 나아가 지식 사이 연결을 직접 고칩니다.
05

REUSE

반복을 Skill로, 공유를 Plugin으로

매번 같은 배경과 절차를 설명하지 않도록 업무 규칙을 Skill로 만듭니다. 다른 질문에서도 같은 규율을 지키는지 검증하고, 동료가 설치할 수 있는 단위가 필요하면 필요한 구성요소만 Plugin으로 묶습니다.

  • SkillAI가 따라야 할 절차, 기준, 출력 형식을 담는 업무 매뉴얼입니다.
  • PluginSkill과 연결 도구를 동료에게 배포하는 설치 단위입니다.
06

BUILD

계획 모드로 웹앱 만들기

Claude Code를 쓰지 않는 동료에게 결과를 전달해야 할 때는 웹앱이 좋은 공유 표면이 됩니다. 요구사항을 계획으로 정리한 뒤 화면, 데이터, 배포의 세 층으로 나누어 최소 기능부터 구현합니다.

  • 계획과 실행무엇을 만들지 합의한 뒤 코드를 작성해 방향 전환 비용을 줄입니다.
  • 작게 배포핵심 사용 흐름을 먼저 만들고 실제 사용을 통해 확장합니다.
07

ACCUMULATE

GitHub에서 축적하고 반복하기

Git은 폴더의 변경 이력을 남기는 타임머신이고 GitHub는 그 저장소를 협업 공간으로 바꿉니다. Issue로 문제를 기록하고 Pull Request로 변경을 검토하며, 자리를 비운 동안에도 원격 작업을 이어갈 수 있습니다.

  • 변경 이력무엇이 왜 달라졌는지 남기고 필요할 때 안전하게 되돌립니다.
  • 협업 표면파일뿐 아니라 문제, 제안, 검토 과정을 함께 축적합니다.
08

CASES

동료가 실제로 만든 프로젝트

규정·법령 검색, 문서 변환, 로컬 문서 검색, Wiki 그래프, 사업정보 앱처럼 각자 작게 시작한 도구가 어떻게 업무 흐름을 바꾸는지 살펴봅니다. 중요한 것은 도구의 개수가 아니라 문제와 연결 방식입니다.

  • 작은 문제반복해서 시간을 쓰는 구체적인 업무 하나에서 시작합니다.
  • 공개 가능한 구조내부 자료와 공개 코드를 구분해 동료가 재사용할 수 있게 만듭니다.
09

KEEP LEARNING

트렌드를 계속 따라가는 방법

새 기능을 모두 좇기보다 공식 문서와 신뢰할 수 있는 실험을 통해 자신의 업무 흐름에 필요한 변화를 골라냅니다. 작은 프로젝트를 지속적으로 고치고 기록하는 것이 가장 현실적인 학습 방법입니다.

과정의 마지막 질문 — 내일 바로 다시 해볼 업무 하나는 무엇이며, 그 과정을 어떻게 파일과 기록으로 남길 것인가?
