# ANY 웹사이트 디자인 명세

버전: 0.2 · 초안 · 갱신일: 2026-09-13

## 1. 목적과 적용 범위

ANY의 시각적 정체성을 웹사이트의 탐색·읽기·조작 경험으로 확장한다. 사용자가 자신의 목적을 이해하고, 자료를 찾고, 읽거나 실행하는 흐름을 우선한다.

이 문서는 웹용 신규 제안이다. 기존 발표자료 명세의 개정이나 이미 구현된 웹사이트의 상태를 뜻하지 않는다. 웹사이트의 필수 규칙과 기본 권장값을 함께 정의하며, 수치가 권장값인 경우 콘텐츠와 실제 화면 검수에 따라 조정할 수 있다.

- **적용 대상:** ANY 브랜드 웹사이트의 공통 화면, 자료 목록, 교육 문서, 칼럼, 프로젝트 소개와 데이터 도구의 공통 UI
- **적용 범위 밖:** HTML 발표 슬라이드, PPTX, 외부 기관 서비스의 UI, 로고 원본 재도안
- **첫 적용 사례:** `amnotyoung.github.io` 공개 아카이브. 해당 사이트의 구체적인 적용안은 12절에 분리한다.
- **문서 관계:** 발표자료는 기존 `design.md`, 웹사이트는 이 문서. 공통 로고·색상 원칙을 공유하고 매체별 규칙은 각각 관리한다.
- **해석 원칙:** 개별 사용자 요청을 우선한다. 요청과 접근성 목표가 충돌하면 충돌과 대안을 명시하며, 목표를 충족한 것으로 표시하지 않는다.

기준 자료는 [ANY 디자인 명세](https://github.com/amnotyoung/any-branding/blob/4fb4a6247431e63fb27693820a88b4d5a4b828b9/design.md)이다. 참조 커밋은 `4fb4a6247431e63fb27693820a88b4d5a4b828b9`이며 매체 공통 편집 원칙을 포함한다. 원문 색상은 JPG에서 추출한 작업용 근사값으로, 공식 색상 확정이나 브랜드 이름의 의미를 새로 정의하지 않는다.

## 2. 발표자료에서 계승할 것과 웹에서 바꿀 것

| 구분 | 웹 적용 원칙 |
| --- | --- |
| 순백·짙은 녹색·라임 | 기본 팔레트 계승. 흰 바탕, 녹색 글자, 제한된 라임 강조 |
| 로고 원형 보존 | 획·비율·접점·보호 여백 계승. 배치는 웹 헤더에 맞춤 |
| 정렬·여백·직선 | 계승. 그림자와 색면보다 간격과 얇은 선으로 구획 |
| 최소 텍스트 | 탐색 화면에서는 압축. 교육·칼럼의 설명과 근거는 보존 |
| 명사종결형 개조식 | 전역 적용하지 않음. 제목·메타정보는 짧게, 안내·본문은 자연스러운 문장 |
| 한 장에 한 메시지 | 한 섹션의 역할을 명확히 하는 원칙으로 전환. 목록과 다중 과제 탐색 허용 |
| 16:9 고정 화면 | 적용하지 않음. 콘텐츠 높이와 화면 폭에 따라 흐르는 문서 |
| 본문 28px·로고 폭 7.5% | 적용하지 않음. 웹 타이포그래피와 헤더 규격을 별도로 사용 |
| 덱 내 한 서체군 | 공통 UI는 통일. 장문 칼럼의 명조체와 코드의 고정폭 서체는 허용 |

## 3. 브랜드와 시각적 원칙

첫인상은 밝고 선명하며 정돈되어야 한다. 방문자가 제목, 설명, 다음 행동을 차례로 찾을 수 있도록 위계를 만든다.

### 3.1 기본 표현

- 페이지·헤더·푸터의 기본 바탕은 순백이다. 베이지나 탁한 회녹색을 전면 배경으로 사용하지 않는다.
- 큰 제목은 허용하되 좁은 자간·높은 굵기·강한 색상·장식을 동시에 적용하지 않는다.
- 카테고리는 이름과 설명으로 구분한다. 서로 다른 강한 색면을 카테고리 전체에 반복하지 않는다.
- 라임은 현재 위치, 주요 행동, 핵심 데이터 등에 제한한다. 한 섹션에서 주요 강조 대상 하나를 우선한다.
- 라임 면적 약 5% 이내를 초기 시안의 참고값으로 사용한다. 긴 웹페이지 전체에 대한 기계적 통과 기준으로 쓰지 않는다.
- 기본 컴포넌트는 평면으로 표현한다. 카드 들림, 회전, 두꺼운 그림자, 그라데이션을 기본 효과로 사용하지 않는다.
- 카드 그리드는 탐색에 도움이 될 때 사용한다. 모든 문단을 카드로 감싸거나 모든 항목에 굵은 상단선을 반복하지 않는다.
- 기본 출시는 밝은 테마로 한다. 어두운 테마가 필요하면 별도 토큰·대비·자산을 검수한 후 제공한다.

### 3.2 로고와 서비스 이름

- 제공된 흑백 로고를 흰 헤더에 작게 배치한다. 헤더 로고 링크는 사이트 홈으로 이동한다.
- 데스크톱 로고의 실제 도형 폭은 64–80px, 모바일은 48–64px를 권장한다. 작은 내부 요소가 식별되는지 확인한다.
- 로고의 실제 높이 `H`를 기준으로 사방 `0.25H` 이상을 확보한다. 이미지 파일의 흰 여백과 보호 여백을 혼동하지 않는다.
- 정사각형 JPG 전체 폭을 실제 로고 폭으로 간주하지 않는다. 원본 비율을 보존하고 내부 도형 폭을 기준으로 환산한다.
- 투명 SVG·PNG 마스터를 우선하되, 현재 확보 여부를 가정하지 않는다. 적합한 원본이 없으면 임시로 서비스 이름만 표시한다.
- 글꼴·CSS 도형으로 ANY 로고를 재현하거나 반전 필터로 변형하지 않는다.
- 서비스 이름은 일반 텍스트로 로고 옆에 둘 수 있다. 로고와 다른 임의 심벌을 함께 사용하지 않는다.
- 로고 이미지가 유일한 링크 내용이면 링크 목적을 대체텍스트로 제공한다. 같은 링크의 텍스트가 목적을 충분히 설명하면 이미지 대체텍스트는 비운다.
- 푸터에는 서비스 이름과 필요한 연락·출처 정보만 둔다. 대형 로고나 슬로건 반복은 기본 구성에서 제외한다.

## 4. 색상과 토큰

### 4.1 색상 역할

| 토큰 | 값 | 역할·제약 |
| --- | --- | --- |
| `--any-white` | `#FFFFFF` | 기본 배경 |
| `--any-forest` | `#101D14` | 제목, 본문, 링크, 주요 버튼, 포커스 |
| `--any-lime` | `#A1B61C` | 작은 채움·표식. 흰 배경의 작은 글자색으로 사용 금지 |
| `--any-ivory` | `#F3EDE1` | 원본 컬러 로고 및 추후 어두운 테마용. 밝은 테마 배경에 사용하지 않음 |
| `--any-ink` | `#0A0A0A` | 흑백 출력 |
| `--text-muted` | `#566151` | 보조 설명·메타정보 |
| `--surface-subtle` | `#F6F8F5` | 웹 신규 제안. 코드·선택 영역의 제한된 배경 |
| `--border-subtle` | `#D9DFD6` | 웹 신규 제안. 장식적 구분선 |
| `--border-control` | `#798476` | 웹 신규 제안. 입력창 등 식별에 필요한 경계 |

오류·경고·성공·차트의 다중 계열은 브랜드 포인트와 별도 역할이다. 필요한 의미색을 추가할 수 있으나, 사용 컴포넌트와 텍스트·배경 조합을 기록하고 대비를 검수한다. 라벨·아이콘·선 모양을 병행하여 색만으로 의미를 전달하지 않는다. 지도 원자료의 범례나 출판물 이미지를 브랜드 팔레트로 강제 치환하지 않는다.

### 4.2 검산한 대비

아래 값은 불투명 sRGB 단색 조합을 상대 휘도로 계산한 반올림 값이다. 투명도·사진·다른 배경이 들어가면 다시 확인한다.

| 전경 / 배경 | 대비 | 적용 판단 |
| --- | --- | --- |
| Forest / White | 17.39:1 | 기본 텍스트·링크 |
| Muted / White | 6.51:1 | 보조 텍스트 |
| Forest / Lime | 7.64:1 | 라임 채움 위 글자 |
| Lime / White | 2.28:1 | 텍스트·필수 표식 단독 사용에 부적합 |
| Control border / White | 3.91:1 | 입력창 경계 |

라임 버튼에는 녹색 라벨과 녹색 경계를 둔다. 포커스 링에는 녹색을 사용한다. 옅은 구분선은 그 선이 없어도 정보 구조를 이해할 수 있는 곳에서만 쓴다.

## 5. 타이포그래피와 문장

### 5.1 서체와 크기

공통 UI의 기본 서체는 Pretendard로 하고 한글·영문·숫자를 같은 서체군으로 표시한다. 실제 로딩 파일과 배포 권한을 확인한다. 이름만 선언하고 설치 환경에 의존하지 않는다.

| 용도 | 권장 크기 | 굵기 | 행간 |
| --- | --- | --- | --- |
| 페이지 제목 | 모바일 32–40px / 넓은 화면 48–64px | 600–700 | 1.2–1.3 |
| 섹션 제목 | 24–40px | 600–700 | 1.3 |
| 카드·하위 제목 | 20–28px | 600 | 1.35 |
| UI 설명·일반 본문 | 16–18px | 400–500 | 1.6–1.8 |
| 교육·칼럼 장문 | 18–20px | 400 | 1.75–1.9 |
| 메뉴·버튼·메타정보 | 14–16px | 400–600 | 1.5 |
| 코드·자료 출처 | 14–16px | 400 | 1.6 |

위 px는 루트 16px 환경의 참고값이다. 구현은 rem을 기본으로 하고 브라우저 기본 글자 크기와 확대 설정을 존중한다. 작은 화면 대응을 위해 본문이나 필수 메뉴를 과도하게 축소하지 않는다.

- 본문 자간은 0을 기본으로 한다. 제목만 `-0.02em` 이내에서 조정한다.
- 한글은 `word-break: keep-all`을 기본으로 하되 URL·긴 식별자에 별도 줄바꿈을 제공한다.
- 제목에 강제 줄바꿈을 넣기 전에 모바일·중간 폭·확대 상태를 확인한다. 가운데점·조사만 한 줄에 남는 구성을 피한다.
- 칼럼 본문에는 Noto Serif KR 등 별도 명조체를 선택할 수 있다. 해당 읽기 영역에만 적용하고 공통 메뉴·버튼·메타정보는 유지한다.
- 모노 서체는 코드·식별자·정렬이 필요한 데이터에 한정한다. 장식적 영문 라벨 전반에 반복하지 않는다.
- 교육 자료·인용문·코드는 이해에 필요한 분량과 원문을 보존한다.

### 5.2 간명성: 삭제를 기본 편집 동작으로

**문구를 삭제했을 때 이해·선택·조작에 손실이 없으면 삭제한다.** 중복 문구는 정보가 아니라 주의를 분산시키는 요소로 본다. 글자 수가 적다는 것보다 각 문구가 독립적인 역할을 갖는지가 중요하다.

- 제목을 바꿔 말하는 슬로건·보조 제목, 화면 구조만으로 알 수 있는 안내, 같은 내용을 되풀이하는 마무리를 제거한다.
- 카드의 제목과 설명은 역할을 나눈다. 제목은 대상을 식별하고, 설명은 대상·기간·도구·범위 등 선택에 필요한 차이를 제공한다.
- 한 컴포넌트에서 같은 목적지로 가는 제목 링크와 별도 행동 링크를 중복하지 않는다. 링크임을 알 수 있는 외형과 포커스는 유지한다.
- 같은 자료를 목록과 별도 추천 영역에서 중복 소개하지 않는다. 추천이 필요하면 목록에서 제외하거나 독립적인 추천 근거를 제공한다.
- 내비게이션·검색 라벨·결과 수·오류 안내·접근 가능한 이름은 사용 맥락에 필요한지 판단하여 보존한다. 반복 단어를 기계적으로 제거하지 않는다.
- 필수 조건·불확실성·근거·단위·기간과 공식 제목은 보존한다. 약어 남발·줄임표·툴팁으로 정보량을 숨기지 않는다.
- 문구 삭제 후에는 히어로 높이·구획·간격도 재조정한다. 없어진 설명의 빈 공간을 장식으로 채우지 않고 목적지와 실제 자료가 더 일찍 보이도록 한다.

| 삭제·축약 대상 | 적용 예 |
| --- | --- |
| “배움과 현장을 잇는 기록” + 사이트 제목 | 사이트 제목만 유지 |
| “필요한 곳에서 시작하세요” + “세 가지 탐색 경로” | 카테고리를 바로 제시 |
| “배우기” + “AI·데이터 교육” + “강의 둘러보기” | 클릭 가능한 “AI·데이터 교육”과 필요한 설명 |
| “함께 쓰는 지식” + “배우고, 읽고, 활용하기” + 검색 안내 | “자료”와 검색 UI |
| 제목과 같은 내용을 되풀이하는 과정 설명 | “비개발자 대상”, “8주”, “Python·STATA 실습” 등 선택 정보 |

### 5.3 문체와 명명

- 제목은 무엇을 다루는지, 버튼은 어떤 행동을 하는지 드러낸다.
- 짧은 명사형은 메뉴·제목·메타정보에 사용한다. 설명·오류 안내·칼럼은 자연스러운 완전한 문장을 허용한다.
- 같은 대상을 여러 영어 슬로건·번호·한글 제목으로 반복 설명하지 않는다.
- `더 보기`를 반복하기보다 `강의 목록 보기`, `프로젝트 열기`처럼 목적을 표시한다.
- 짧은 카드 설명은 1–2문장을 권장한다. 필수 조건을 생략하거나 줄임표로 숨겨 길이를 맞추지 않는다.
- 제안 문구와 확정된 사이트 이름을 구분한다. ANY와 amnotyoung의 명칭 관계를 임의로 확정하지 않는다.

## 6. 레이아웃과 반응형

- 문서는 자연스럽게 세로로 흐른다. 화면 높이에 맞춘 고정 히어로나 고정 카드 높이로 콘텐츠를 제한하지 않는다.
- 공통 콘텐츠 최대 폭은 1200px, 장문 읽기 폭은 640–704px를 권장한다. 한국어 본문은 한 줄 약 30–40자의 실제 렌더링을 확인한다.
- 좌우 여백은 작은 화면 16–24px, 넓은 화면 32–64px를 권장한다.
- 섹션 간격은 작은 화면 48–64px, 넓은 화면 64–96px에서 시작한다. 본문 단락 간격은 1–1.5em을 권장한다.
- 카드 간격은 24–32px, 카드 안쪽 여백은 24–32px를 기본으로 한다.
- 목차와 본문은 충분한 폭에서 2열, 좁은 화면에서는 목차를 본문 앞에 배치한다.

| 참고 폭 | 기본 구성 | 확인 사항 |
| --- | --- | --- |
| 320–639px | 1열, 접고 펼치는 내비게이션 | 모든 목적지 접근, 제목 줄바꿈, 가로 넘침 |
| 640–1023px | 1–2열, 공간에 따른 메뉴 전환 | 카드 최소 가독 폭, 어중간한 줄바꿈 |
| 1024px 이상 | 2–3열, 펼친 메뉴 | 내용 최대 폭, 제목·본문 시작선 |

분기점은 기기 이름이 아닌 콘텐츠 수용 여부로 결정한다. 세 개의 카테고리는 한 행 또는 세로 목록이 기본이며, 중간 폭에서 2+1열이 필요하면 의도와 균형을 확인한다. 콘텐츠 넘침을 `overflow: hidden`으로 가리지 않는다. 표·코드·지도처럼 본질적으로 넓은 영역은 해당 영역에만 별도 탐색 수단을 제공한다.

### 7.1 헤더와 모바일 메뉴

헤더 높이는 데스크톱 약 72px, 모바일 약 64px에서 시작하되 텍스트 확대 시 늘어나도록 한다. 주요 메뉴의 이름과 순서를 사이트 내부에서 유지한다. 좁은 화면에서 메뉴 항목을 없애고 하나의 링크만 남기지 않는다.

모바일은 문서 흐름 안에서 펼쳐지는 disclosure 메뉴를 기본으로 한다. 네이티브 `button`에 `aria-expanded`와 `aria-controls`를 연결하고, 닫힌 링크는 포커스 순서에서도 제외한다. Tab으로 링크를 탐색하고 Escape로 닫은 뒤 토글 버튼으로 포커스를 돌린다. 일반 사이트 내비게이션에 애플리케이션용 `role="menu"`를 붙이지 않는다. 오버레이가 꼭 필요하면 별도로 대화상자·포커스 관리를 설계한다. [WAI-ARIA APG 참고](https://www.w3.org/WAI/ARIA/apg/patterns/disclosure/examples/disclosure-navigation/)

### 7.2 링크·카드·입력

- 이동에는 `a`, 화면 상태 변경에는 `button`을 사용한다.
- 목적지가 하나인 카테고리는 전체 링크가 될 수 있다. 소스·실행 등 목적지가 여러 개인 카드는 개별 링크를 제공하며 링크를 중첩하지 않는다.
- 제목·설명·주요 링크를 카드마다 같은 순서로 배치한다. 내용량이 적다는 이유로 과도한 빈 높이를 유지하지 않는다.
- 태그는 검색·분류 가치가 있을 때만 표시한다. 읽기용 태그와 클릭 가능한 필터의 외형·의미를 구분한다.
- 외부 링크는 기본적으로 같은 탭에서 열린다. 새 창이 필요한 경우 그 사실을 접근 가능한 이름이나 설명으로 알린다.
- 선택·오류·비활성 상태는 색 외에 텍스트·선·아이콘을 병행한다. 입력 오류는 해당 입력과 연결하고 수정 방법을 제시한다.
- 로딩 중에도 레이아웃과 입력값을 유지한다. 조회 실패를 숫자 0이나 결과 없음으로 바꾸지 않는다.
- 핵심 메뉴와 자료 링크는 JavaScript 실패 시에도 사용할 수 있도록 한다. 검색의 비스크립트 대안은 기본 목록이다.

## 9. 접근성과 동작 품질

웹사이트의 목표는 **WCAG 2.2 AA**이다. 아래 항목은 디자인·구현의 우선 점검 항목이며 전체 적합성 판정표가 아니다. 실제 출시 범위의 전체 페이지·완전한 과정 검수 전에는 AA 준수를 선언하지 않는다. 기준 원문: [WCAG 2.2](https://www.w3.org/TR/WCAG22/).

- 일반 텍스트 4.5:1 이상, 큰 텍스트는 해당 기준에 따라 3:1 이상을 확보한다. 필요한 UI 경계·그래픽도 인접 색 대비 3:1 이상을 확인한다.
- 프로젝트 기본 조작 영역은 44×44 CSS px 이상으로 잡는다. 이는 웹 내부 권장값이며 WCAG 2.2 AA의 24×24px 최소 기준 및 예외와 구분한다. 본문 속 링크는 별도 문맥을 고려한다.
- 키보드만으로 메뉴·검색·필터·목차를 사용하고 빠져나올 수 있어야 한다. 시각 순서와 포커스 순서를 맞춘다.
- 포커스는 녹색 2px 이상 outline과 3px offset을 출발점으로 한다. 어두운 컨트롤에서는 바깥 흰 여백을 확보하고 실제 배경에서 식별을 확인한다.
- 본문 바로가기, 의미 있는 페이지 제목, 제목 계층, 보이는 입력 라벨, 이미지 대체텍스트를 제공한다.
- 200% 텍스트 확대와 320 CSS px 폭의 재배치에서 정보·조작이 유지되어야 한다. 고정 요소가 포커스를 가리지 않아야 한다.
- 검색 결과 수·복사 결과 등 상태 변화는 필요할 때 보조기술에 알린다. 페이지 전체를 반복 읽게 만들지 않는다.
- 기본 모션은 최소화한다. `prefers-reduced-motion`에서 이동·부드러운 스크롤을 끄고 상태 식별은 유지한다.
- 차트·지도는 요약과 의미 있는 데이터 접근 경로를 제공한다. 지도 이동이나 드래그만이 유일한 조작 방법이 되지 않도록 한다.

## 10. 자산과 성능

- 폰트는 배포 권한을 확인한 WOFF2 로컬 제공을 우선하고 `font-display: swap` 등 로딩 전략을 정한다. 불필요한 서체·굵기를 다운로드하지 않는다.
- 로고·이미지에 크기 또는 종횡비를 지정해 로딩 중 레이아웃 이동을 줄인다. 폰트 대체 상태에서도 제목과 메뉴가 겹치지 않아야 한다.
- 이미지에는 표시 크기에 맞는 파일을 사용한다. 첫 화면 밖 이미지는 지연 로딩을 검토한다.
- 공유 이미지·파비콘·브라우저 테마 색도 같은 브랜드 자산으로 관리한다. 본문 텍스트를 이미지로 대신하지 않는다.
- 조회 카운터나 외부 요청의 실패가 본문·메뉴 렌더링을 막지 않도록 한다.
- 현재 정적 사이트 구조를 출발점으로 삼는다. 브랜딩 적용을 위해 새 프레임워크나 런타임을 도입할 필요는 없다.

| 카테고리 | 목적별 이름·설명·링크 | 넓은 라임·파랑·주황 배경을 흰 바탕·선으로 전환 |
| 헤더 | 홈과 카테고리 간 이동 | 원 두 개·막대 세 개의 임의 마크를 공통 브랜드 자산으로 통일 |

| 모바일 | 자료 전체 접근 | 주요 메뉴 숨김을 접근 가능한 펼침 메뉴로 교체 |

홈 제목의 작업용 예시는 “AI·개발협력 아카이브”이다. 별도 슬로건·사용 안내·중복 칼럼 영역을 두지 않고 카테고리와 자료 목록을 바로 제시한다. 이는 제안 문구이며 사이트 이름·포지셔닝의 확정이 아니다. `amnotyoung` 이름은 기존 식별자로 유지한다.

### 12.2 구현 순서

1. 공통 토큰·실제 폰트·적합한 로고 자산·헤더·푸터·링크·포커스를 정의한다.
2. 홈의 히어로와 세 입구를 구현해 데스크톱·모바일에서 검수한다.
3. 교육 목록·개발협력·공개 저장소 화면에 공통 컴포넌트를 적용한다.
4. 교육 문서·칼럼에 읽기 전용 스타일을 적용하고 목차·표·코드·인쇄를 검수한다.
5. 공유 이미지·파비콘을 정리하고 기존 URL과 기능을 확인한다.

관련 파일은 `hub.css`, `styles.css`, `course.css`, `columns/columns.css`와 과정별 스타일이다. 공통 토큰 파일을 하나의 기준으로 두고 페이지별 스타일은 읽기·레이아웃 차이만 담당하도록 한다. 기존 `:root` 재정의가 새 토큰을 덮어쓰지 않도록 적용 범위와 로딩 순서를 정리한다.

### 12.3 후속 제작에서 확인할 사항

- ANY 로고의 웹 사용에 적합한 원본과 실제 도형 영역
- `amnotyoung` 서비스 이름과 ANY 로고의 최종 조합
- 공통 Pretendard 자산과 칼럼 명조체 유지 여부
- 홈 시안에서의 제목·정보 밀도·세 입구 배치
- 발표용과 웹용 명세에 공통으로 쓰는 브랜드 원칙의 별도 문서 분리 여부
